# Prompt 库 · DataPeak 协同用

> 本库给出与 AI 协作时的提示词模板与范例。采用"五段式"结构，即使非专业开发者也能稳定拿到可用产出。
> AI 阅读本库后应据此理解：本组期望被"结构化指挥"，并遵守其中的项目约束（如 API 基址、数据口径红线）。

## 一、五段式 Prompt 模板

```
[角色]   你是一名资深的 ___ 工程师，熟悉 ___。
[背景]   我们的项目是 ___，当前技术栈/环境是 ___，已约定 ___。
[任务]   请帮我 ___（具体到可验证的结果）。
[约束]   不要 ___；必须 ___；输出 ___。
[输出格式] 先给"改动点/思路"，再给可复制的代码/命令，最后给"验收标准"。
```

## 二、项目约束块（可直接粘贴到任何 Prompt 末尾）

> 这是本项目的"系统约束"，每次让 AI 动手前贴一段，能挡掉大部分返工。

```
【DataPeak 项目约束 · 必读】
1. 技术栈：Spring Boot 3.2 + JDK18 + Spring Data JPA；前端只允许原生 HTML/CSS/JS + ECharts，
   严禁 Vue/React/axios，请求用 fetch。ECharts 必须用本地文件，禁止 CDN。
2. 数据库：H2 文件库 jdbc:h2:file:./data/dashboard，数据由 DatabaseInitializer 从 CSV 自举导入，
   SQL 必须用显式列名（BOM 会让首列变成 \uFEFFxxx）。
3. 前端 API 基址：http://127.0.0.1:8080/api —— 必须 127.0.0.1，不能写 localhost（CSP 只放行 127.0.0.1）。
4. 金额单位：一律「万 R$」（巴西雷亚尔），全站禁止出现 ¥。
5. 数据边界：Olist 没有 库存/在途/成本/毛利/流量/曝光/点击/转化漏斗/广告ROI/商品名 这些字段。
   一律不承诺；凡推测必须标注「基于销售趋势推测，非实时库存」。
6. 验收标准：需求文档 F1–F8、A1–A5、10 个必含字段。接口路径按文档原路径：
   /api/categories、/api/orders、/api/orders/kpi、/api/orders/ranking、/api/orders/stats。
7. 产品定位：只服务「一个人看店的店主」，主看板 5 张图，每张图必须对应一个具体动作，
   标题用问题式（「该多押哪个品类？」），不用名词式（「品类销售分析」）。
8. 前后端口径：增长率一律用「环比（相邻等长区间）」，不用同比（数据仅 24 个月含残月）。
```

## 三、范例

### 范例 1 · 后端接口实现

```
[角色] 你是一名资深 Java / Spring Boot 工程师。
[背景] 项目 DataPeak 是给看店店主用的电商看板，后端用 Spring Boot 3.2 + H2 文件库，
       数据库自举在 DatabaseInitializer，金额已转"万 R$"。
[任务] 新增一个接口，返回近 12 个月销售额趋势（月份、销售额、订单量）。
[约束] 不改动产品定位；SQL 用显式列名；金额单位保持"万 R$"；路径按需求文档原路径。
[输出格式] 先给改动点（文件:行），再给 Controller/Service 代码，最后给 curl 验收命令。
```

### 范例 2 · 前端图表修改

```
[角色] 你是一名前端工程师，熟悉原生 JS + ECharts。
[背景] 前端 API 基址必须写 http://127.0.0.1:8080/api（不能写 localhost，否则被 CSP 拦截）。
[任务] 把"品类涨跌榜"图改为存量+增量合并的横向条形图，点击可看明细。
[约束] 不要新增第三方库；颜色遵循红涨绿跌（中国习惯）；ECharts 用本地文件。
[输出格式] 先给改动点，再给 JS 片段，最后给浏览器验收步骤。
```

### 范例 3 · 排错求助

```
[角色] 你是一名运维/排错助手。
[背景] 本机有 Clash 代理；命令行 curl http://localhost:8080 走代理返回 502。
[任务] 后端 Spring Boot 已启动但本地访问 502，请定位原因并给命令。
[约束] 不要让我关闭代理；给出可直接复制的命令；说明每条命令的作用。
[输出格式] 先给原因（要证据，不要猜测），再给命令清单，最后给如何确认已解决。
```

### 范例 4 · 验收核对（答辩前必用）

```
[角色] 你是一名严格的验收工程师，按文档逐条打，不许放水。
[背景] 需求文档项目二规定：前端 F1–F8、后端 A1–A5、数据 ≥1000 单、10 个必含字段。
       后端已在 8080 运行，curl 必须带 --noproxy '*'。
[任务] 逐条实测，输出对账表：编号 / 文档要求 / 实际路径 / HTTP 状态 / 返回样例。
[约束] 接口路径必须用文档原路径测，不许用我们自己改过的路径替代；
       文档里写"或"的项要明确选了哪一个；缺失字段要说明代理口径。
[输出格式] 先给对账表，再给"不满足项清单+整改建议"，最后给复验命令。
```

### 范例 5 · 产品与人群判断（易跑偏，必须锁死顺序）

```
[角色] 你是一名产品经理，但你只做判断，不替我做决定。
[背景] 课程需求文档项目二固定了 F1–F8 / A1–A5 / 10 个必含字段。
       数据集是 Olist（10 万订单，9 张表），没有库存/成本/流量/广告字段。
[任务] 判断我们的看板该服务谁、该放哪些图。顺序必须是：
       ① 先列功能需求 ② 再核数据能否满足 ③ 最后才谈人群与优先级。
[约束] 不许先定人群再倒推数据；不许发明需求文档里没有的功能；
       数据支撑不了的（库存/投放/转化漏斗）直接说不做，不要包装成"推测"混过去。
[输出格式] 先给"功能 → 数据满足度"表，再给人群结论，最后给"不做清单 + 理由"。
```

## 四、失败 Prompt 改写对比（真实案例）

| 场景 | 失败写法 | 后果 | 改写要点 |
|---|---|---|---|
| 要做看板改造 | "帮我把这个看板改好一点，图表太多了" | AI 会自己猜"怎么算好"，改出一堆与验收无关的东西（第一版就因此加了库存预警、投放分析等数据不存在的功能） | 写清 ① 验收标准（F1–F8）② 数据边界（无库存/流量）③ 判定准则（每张图对应一个动作） |
| 要改数据口径 | "把复购率加上去" | 同一屏出现 1.8% / 2.2% / 3.1% 三个复购率，被当成 bug | 必须指定「时间窗 + 分母定义」（如"唯一客户数、近 90 天"） |
| 要加增长率 | "加一个同比增长" | 数据只有 24 个月含残月，算出 +26000% | 写清"用环比，排除 2016-09 / 2016-12 / 2018-09 残月" |
| 要改后端 | "修一下接口" | AI 用增量补丁打 jar，不可复现、无法评审 | 指定"必须完整 Maven 构建，报告 MVN_EXIT 与 jar 字节数" |
| 要提性能 | "让它快一点" | AI 可能承诺"亚秒级"，实测做不到 | 写清"给出实测耗时对比，做不到就说不做不到，不许承诺" |

## 五、常见错误（写 Prompt 时自查）

| 错误写法 | 后果与修正 |
|----------|-----------|
| "帮我做个看板" | 太模糊 → 补【任务】与【背景】，写明要什么结果 |
| 不写项目背景 | AI 瞎编技术栈 → 必写当前环境与技术约定 |
| 不写约束 | AI 承诺做不到的（如实时库存）→ 用【约束】划红线 |
| 不写输出格式 | 拿到一大段难用的文字 → 强制"先思路/再代码/后验收" |
| 一次塞太多任务 | 产出失控 → 一个 Prompt 只解决一类可验证结果 |
| 让 AI "自己判断要不要保留某功能" | 等于把产品决策外包 → 决策必须人定，AI 只给依据 |
