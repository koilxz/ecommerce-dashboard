# 协同 SOP 文档 · DataPeak 电商看板

> SOP（标准作业流程）把"人机会如何配合完成一类任务"固化成可复用步骤，降低对个人技术的依赖，保证协同质量一致、可追溯。AI 阅读本文后应据此理解本组的协作流程与必须停下的复核点。

## SOP 标准写法（字段模板，本文所有 SOP 必须五段齐全）

| 字段 | 要求 |
|---|---|
| **编号 / 名称** | 唯一标识 + 一句话用途 |
| **适用场景** | 什么情况下启用本流程 |
| **角色与步骤** | 逐条写明"谁（人/AI）做哪一步"，标注产出物 |
| **闸门 / 复核点** | 哪些步骤必须停下来由人确认 |
| **产出与记录** | 流程结束交付什么、留下什么以供追溯 |

---

## SOP-DV-01 需求转实现流程

- **适用场景**：把一条产品需求变成可运行代码
- **角色与步骤**：
  1. **人**：写需求卡（目标用户、要解决的一个动作、明确不要什么）→ 产出《需求卡》
  2. **人**：将需求卡转为结构化 Prompt 交给 AI（模板见《03-Prompt库.md》）→ 产出 Prompt 记录
  3. **AI**：先给改动点（文件:行 + 为什么改），再给代码 → 产出差异说明 + 代码
  4. **人**：按"看到 XX 才算完成"的验收标准运行确认 → 产出验收记录
- **闸门 / 复核点**：
  - 涉及产品定位 / 砍功能 / 对外口径 → **人拍板，AI 不得代定**
  - 纯技术实现 → AI 可直接做，但改动点必须可复核
  - 涉及删除 / 登录 / 账号 / 凭据 → **人亲自执行**
- **产出与记录**：《需求卡》+ 代码 + 验收记录，三者同存于 `docs/` 或提交记录

## SOP-DV-02 AI 产出人工复核清单

- **适用场景**：所有 AI 生成的**对外**内容（图表结论、数据口径、答辩话术、文档/PPT）
- **角色与步骤**：
  1. **AI**：交付时自报"哪些是实测、哪些是推测、哪些没验证" → 产出三条自述
  2. **人**：逐项对照下面 5 条复核 → 产出复核结论（通过/打回）
  3. **人**：打回项写明理由，交回 AI 重做 → 产出打回记录
- **复核项（5 条，缺一不可，任一项不过即打回）**：
  1. **真实性**：数据有无编造？推测项是否显式标注？
  2. **边界**：是否越界承诺了拿不到的数据（库存 / 成本 / 毛利 / 流量 / 投放 ROI）？
  3. **验收**：是否满足需求文档对应条款（F1–F8 / A1–A5 / 10 个必含字段）？
  4. **一致性**：是否与已定定位冲突（林姐 / 5 张图 / 万 R$ / 问题式标题）？同屏多处数字口径是否一致？
  5. **可解释**：能否用一句人话说清"这数字怎么来的"？
- **闸门 / 复核点**：**一票否决**——上述任一项不通过，打回重做，不计为交付。
- **产出与记录**：复核结论 + 打回记录（含理由），作为答辩"人是否真把关"的证据

## SOP-DV-03 排错协同流程

- **适用场景**：运行 / 构建 / 接口报错
- **角色与步骤**：
  1. **人**：复制**完整**报错 + 环境（系统 / 端口 / 代理状态 / 是否已启动）→ 产出报错快照
  2. **AI**：定位根因（给证据，不给猜测）+ 给出可复制命令 → 产出根因说明 + 命令
  3. **人**：确认命令安全后执行 → 产出执行结果
  4. **人**：验证问题已解决
  5. **人 + AI**：把该坑写回 `.workbuddy/memory/`（反馈闭环，见 SOP-DV-07）→ 产出沉淀条目
- **闸门 / 复核点**：
  - 涉及删除 / 清空 / `rm -rf` / `taskkill` / 账号登录 → **人确认后执行，AI 不代办**
  - AI 第一次定位错误时，**人须要求"再给证据"而不是换方案试错**
- **产出与记录**：已解决的问题 + 沉淀的排错知识（`memory/` 条目）

## SOP-DV-04 数据口径把关流程

- **适用场景**：任何涉及"数据含义"的表述（图表标题、KPI 标签、答辩话术、文档）
- **角色与步骤**：
  1. **AI**：给出该表述依赖的字段与计算口径 → 产出"字段 → 口径"对照
  2. **人**：核对字段是否真实存在（查表结构，不查印象）→ 产出核对结论
  3. **人**：对不存在或需推导的项，决定"降级 / 标注 / 删除"→ 产出处理决定
- **规则（红线）**：
  - Olist 拿不到的（库存 / 在途 / 成本 / 毛利 / 流量 / 曝光 / 点击 / 转化漏斗 / 广告 ROI）**一律不承诺**
  - 需构造的口径（"我的店"=`seller_id` 切片、"商品名"=中文品类 + ID 后 6 位、补货=趋势外推）**必须显式标注**
  - 同一指标多处出现时，**必须标时间窗**（例：复购率 1.8% 标"近 90 天"），避免同屏数字打架
  - 金额单位统一「万 R$」，全站禁止出现 ¥
- **闸门 / 复核点**：涉及数据含义的对外文字，发布前须经人复核（走 SOP-DV-02）
- **产出与记录**：口径对照表（字段 → 口径 → 标注文案）

## SOP-DV-05 构建与重启流程（本项目高频，易踩坑）

- **适用场景**：后端代码改动后需要重新构建并验证服务可用
- **角色与步骤**：
  1. **人**：确认没有运行中的 java 进程（运行中的进程会锁住 jar，导致 repackage 失败）→ 产出进程状态
  2. **人**：执行构建命令（IDEA 自带 Maven + 阿里云镜像）→ 产出 `BUILD` 结果
  3. **人**：**必须显式**指定端口启动（环境变量 `SERVER__PORT` 会覆盖配置）→ 产出启动日志
  4. **AI / 人**：打 `/api/ready` 确认数据就绪（200 才算起好）→ 产出就绪证据
  5. **AI / 人**：按 SOP-DV-06 抽查接口 → 产出验证结果
- **闸门 / 复核点**：
  - **禁止用"解 jar + javac 增量编译 + 重新打包"当作交付构建**（不可复现，无法评审）
  - 启动必须带 `--server.port=8080`，否则端口被环境变量改掉
  - 构建失败时先看 jar 是否被占用，不要盲目重试
- **产出与记录**：jar 时间戳 + 字节数 + `MVN_EXIT` + `/api/ready` 结果

## SOP-DV-06 验收核对流程（按需求文档逐条打）

- **适用场景**：里程碑验收前 / 答辩前自查
- **角色与步骤**：
  1. **AI**：从需求文档抄出 F1–F8、A1–A5、数据要求清单（**抄原文，不改写**）→ 产出对账清单
  2. **AI / 人**：逐条实测（`curl --noproxy '*'` 打接口 / 浏览器点页面）→ 产出原始返回
  3. **人**：判定每项"满足 / 代理 / 不满足"，不满足的登记整改 → 产出对账表
  4. **AI**：修完再跑一遍步骤 2–3，闭环 → 产出复验记录
- **闸门 / 复核点**：
  - **接口路径必须按文档原路径实测**（历史教训：`/api/categories` 实际是 `/api/orders/categories`，文档路径 404，会直接丢分）
  - 文档里写"或"的项（如 F7 新老客**或**支付占比），至少满足其一即可，但必须明确选了哪个
  - 数据要求的"必含字段"逐字段核对，缺的必须说明代理口径
- **产出与记录**：F1–F8 / A1–A5 对账表（满足 / 代理 / 不满足）+ 复验记录

## SOP-DV-07 反馈闭环流程（修正回流，避免重复踩坑）

- **适用场景**：人修正了 AI 的产出、或踩到环境/口径坑之后
- **角色与步骤**：
  1. **人**：判断该修正是否**会重复出现**（是 → 必须固化；否 → 记录即可）
  2. **人 + AI**：写成一条可复用条目（现象 / 根因 / 做法 / 判据）→ 产出沉淀条目
  3. **人**：落盘到对应位置——环境与口径坑 → `memory/`；可复用流程 → 本 SOP；提示词经验 → 《03-Prompt库》
  4. **AI**：后续任务开始前先读，避免重复犯错
- **闸门 / 复核点**：只有"会重复出现"的才进 SOP / Prompt 库，避免文档膨胀
- **产出与记录**：`memory/YYYY-MM-DD.md` 条目 + SOP 更新记录
- **本项目已闭环的实例**：CSP 只放行 `127.0.0.1` 导致登录失败（已改 API 基址并写入 Prompt 库范例 2）；`SERVER__PORT` 覆盖端口（已写入 SOP-DV-05）；jar 被运行进程锁住导致构建失败（已写入 SOP-DV-05）
