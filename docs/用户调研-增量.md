# 用户调研-增量：中小电商卖家真实痛点与 DataPeak 价值验证

> **文档目的**：回应老师反馈（"图表太多、没针对具体人群、没真实抓住用户痛点、没实质性帮助"）。在改产品前，用**真实行业调研 + 系统已有真实数据证据**，验证我们"数据太多不会分析"的命题是否成立，并证明每个功能都能转化为对某个人有用的**动作**。
> **产品**：DataPeak 电商销售数据洞察看板　**产品经理**：许清楚（Xu）　**日期**：2026-10-24
> **性质**：仅做研究，不改代码。系统指标来自已验证的 `/api/diagnosis` 等真实 Olist 数据（约 10 万订单，2016-10 ~ 2018-09）。

---

## ① 真实痛点清单（带来源引用）

**来源说明（3 类可信来源）**
- **S1 行业量化调研**：DataGlass Labs《Decision Intelligence Playbook for E-commerce》(2024)，综合 Jungle Scout《State of the Amazon Seller》调研（n=2,164）、Shopify《Commerce Trends 2024》、McKinsey 中小企业调查。
- **S2 跨境行业媒体 / 平台白皮书**：大数跨境（10100.com）汇总 Statista 2024、eMarketer 2024、Amazon Seller Central 2024 库存健康度基准、Jungle Scout 2024 等。
- **S3 产品 / 分析社区**：人人都是产品经理（woshipm）引淘天白皮书"六大痛点"；帆软 / 数跨境 BI 引多平台数据分析门槛调研。

| 痛点 | 真实表现（数据 / 现象） | 来源 |
|------|----------------------|------|
| 选品 / 找利润品难 | 62% 卖家把"找 profitable products"列为头号痛点 | S1 |
| 定价与毛利压力 | 58% 受定价 / 毛利压缩；62% 中国卖家净利率 <15%（2020 为 35%） | S1, S2 |
| 库存积压 / 断货 | 55% 受库存与断货困扰；**40% 失败店铺因库存积压或缺货致现金流断裂**；37% 亏损案例源于选品失误致库存积压 | S1, S2(eMarketer) |
| 广告成本攀升 / ROI | 53% 受获客成本上升困扰；中小卖家 ACoS 中位数 38.2%，远高于健康值 22–28% | S1, S2(Amazon) |
| 现金流 / 周转 | 49% 受现金流与营运资金压力；库存周转 89 天 vs 标杆 52 天 | S1, S2 |
| 退货与差评 | 跨境平均退货率 18%，**服装类高达 35%**；差评 / ODR 影响排名与封店风险 | S2 |
| 多平台 / 多店管理 | **68% 卖家同时运营 3 个以上平台**，跨平台口径不一致致对比误差 >40%；"数据孤岛"为第一难关 | S3(帆软), S2 |
| 数据分析门槛 / 无实质帮助 | 34% 卖家自述缺分析工具（未提示下的高比例）；超 80% 跨境卖家被数据分析卡住；四大门槛含"行动转化：报表很多但销量不变"；淘天白皮书六大痛点含"数据孤岛、工具选型难" | S1, S3 |

> **关键洞察（直接回应老师"没实质性帮助"）**：卖家**不缺图表，缺的是"数据结论 → 具体动作"的最后一公里**。帆软调研明确指出学习门槛的第四关是"行动转化：报表很多但销量不变，没有把数据结论对应到具体动作"；淘天白皮书六大痛点也落在"数据孤岛、工具选型难"而非"没有图表"。这恰好说明老师批评的本质——我们若只堆图表，就会和现有工具一样"没帮助"；必须把结论翻译成动作。

## ② 痛点 → 数据证据对应（用我们系统已有的真实 Olist 指标"戳中"真实困境）

**系统已验证可输出的真实指标（Olist，约 10 万订单）**
- 销售额环比 **+2.8%**（全平台，近周期）
- 平均评分 **4.14**（健康，> 3.5 阈值）
- 延迟发货率 **8.8%**（< 15% 预警线，物流健康）
- 取消率 **0.6%**（极低，健康）
- 品类骤降案例 **「酷玩」环比 −41.9%**（异常）
- 增长案例 **「健康美容」+37.8%**（机会）
- 复购率 **1.8%**（远低于 20% 健康线，留存 / 拉新严重不足）

| 真实痛点 | 系统真实指标证据 | 戳中逻辑 |
|---------|----------------|---------|
| 选品 / 找利润品难 | 「健康美容」+37.8%、「酷玩」−41.9%（品类增速两极） | 用真实数据直接指出"哪个品类在涨 / 在跌"，替代凭感觉选品 |
| 库存积压 / 现金流 | 「酷玩」−41.9% 触发**促销去化**信号；复购率 1.8% 触发**拉新不足**预警 | 下跌品类 + 低复购 = 压货风险，系统建议"清仓 / 停止补货"，避免现金流断 |
| 广告 ROI / 流量焦虑 | 销售额环比 +2.8% + 品类贡献拆解（主要靠某品类带动） | 告诉卖家"钱该投 / 挪到哪个品类"，而非只看总销售额 |
| 退货与差评 | 平均评分 4.14（系统可监测；若 <3.5 即口碑预警） | 把"评分"变成可预警的经营信号，而非后台一个数字 |
| 多平台 / 多店管理 | 卖家视角切换（seller_id 切片，top5 预设店铺） | 每店独立诊断，免跨平台手工拼表（回应 68% 多店、40% 误差） |
| 数据分析门槛 / 无动作 | 经营健康度诊断（一句话结论文案）+ 术语气泡 + 异常预警 | 不懂"环比 / 复购率"也能得到"该清仓 / 该加注"的动作 |

> **诚实标注**：① Olist 无实时库存字段，补货建议用"销售增速 × 口碑"代理指标并标注"推测口径，非真实库存"；② 复购率 1.8% 是 Olist 真实值（其订单天然低频），作为"拉新不足"预警证据有效，但讲解时需说明口径；③ 延迟发货率 8.8%、取消率 0.6% 低于预警线，说明系统既能"报警"也能给"绿灯"，结论更可信。

## ③ 三个人物画像细化（含典型场景与最想要的"实质性帮助"）

### 林姐 · 女装店主（35 岁，不懂数据）
- **真实困境**（贴合 S2 服装退货 35%、S1 选品 / 库存痛点）：选品靠感觉，服装退货率高易压货，看不懂后台"客单价 / 复购率"等术语，最怕"压错款 → 现金流断"。
- **典型场景**
  - **一天**：早 9 点翻昨天订单 Excel → 凭感觉定今天主推款 → 下午回顾客消息 → 晚上纠结要不要参加平台大促。
  - **一周**：周末盘库存发现某款压了 200 件卖不动，却不知该不该继续补、该不该打折。
- **最想要的"实质性帮助"（具体到一个动作）**：打开看板首页，系统用一句话告诉她——"本周『酷玩』类环比 **−41.9%**，建议**停止补货并参加清仓**；『健康美容』**+37.8%**，可**加注主推**"——她直接照做，不必自己算。

### 小吴 · 代运营新人（23 岁，管 5 店）
- **真实困境**（贴合 S3 多店 68%、S1 广告 ROI）：管的 5 个店数据分散在不同后台、口径不一，老板问"这周为啥跌了"答不上，广告 ROI 算不清。
- **典型场景**
  - **一天**：午间拉各店数据截图发群 → 被老板追问"为什么跌"答不上 → 想要能自动给结论的工具。
  - **一周**：周一要给老板交各店健康度周报。
- **最想要的帮助**：用"卖家视角切换"逐个店看「经营诊断」卡片，一键复制系统生成的汇报话术——"本周 X 店销售额环比 **+2.8%**，主要靠健康美容带动；复购率仅 **1.8%** 低于健康线，建议加强老客召回"——直接发给老板，不用自己拼数据。

### 陈总 · 区域经销商（45 岁，怕压错品类）
- **真实困境**（贴合 S1 库存 / 现金流、S2 周转 89 天）：代理多品牌，ERP 报表滞后一周，怕压错品类占死现金流，要快知道"哪出问题"。
- **典型场景**
  - **一天**：晨会看昨日简报 → 问团队"哪出了问题" → 需要预警与诊断支撑。
  - **一周**：周例会要定下月进货结构。
- **最想要的帮助**：看异常预警"『酷玩』品类环比 **−41.9%**"→ 当周**下调该品类进货占比、把预算转给『健康美容』+37.8%**，用真实数据代替拍脑袋定进货。

## ④ 痛点 → 功能 → 动作 映射表（证明每个功能都能变成对某个人有用的动作）

| 真实痛点 | 对应现有 / 新增功能 | 给该角色的具体动作（回应"没实质性帮助"） |
|---------|------------------|----------------------------------------|
| 选品 / 找利润品难 | F5 品类排行 / F6 TOP10 / 增长案例（健康美容 +37.8%） | **林姐**：本周主推健康美容，停补下跌品类 |
| 库存积压 / 现金流 | P1 补货 / 促销信号（促销去化）+ P1 异常预警（酷玩 −41.9%） | **陈总**：当周下调酷玩进货、转预算给增长品类 |
| 广告 ROI / 流量焦虑 | P0 经营诊断（销售额环比 + 品类贡献）+ 支付分布 | **小吴**：把广告预算从低效品类挪到高增长品类 |
| 退货与差评 | P0 诊断（平均评分）+ 用户分析 / 评分监测 | **林姐**：评分跌破阈值即查详情页与质量 |
| 多店管理 | P2 卖家视角切换（seller_id 切片） | **小吴**：逐店切换看独立诊断，免跨平台手工拼表 |
| 数据分析门槛 / 无动作 | P0 卖家语言改造（术语气泡）+ P0 诊断结论文案 + P1 预警 | **林姐 / 陈总**：看一句话结论即可决策，不必懂术语 |

> **结论**：老师"没实质性帮助"的批评，根源是功能停留在"展示"。上表把每个功能都接到一个**角色 + 一个可执行动作**，正是本次增量（诊断结论 + 信号 + 预警 + 卖家语言）要补的"动作闭环"。

## ⑤ 待确认问题（2-3 个）

1. **指标归属口径**：现有 Olist 指标是"全平台聚合"，而人物画像里林姐 / 小吴 / 陈总用的是"seller 视角切片"后的数据。是否在调研 / 演示中统一说明"画像数据为卖家视角切片示例"，避免答辩被问"这些指标怎么对应到具体店主"？
2. **复购率 1.8% 的讲解口径**：Olist 复购率天然极低（1.8%），作为"拉新不足"预警证据很强，是否需要在界面 / 答辩明确"这是数据集特性，真实店铺复购率通常更高"，以免被误读为系统缺陷？
3. **是否补充一手调研**：本次为二手资料 + 系统数据验证；若老师要求"真实用户访谈"，是否要我们补 2-3 个微型访谈（如校内电商创业同学）作为一手佐证？
