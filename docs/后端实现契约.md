# DataPeak 后端实现契约（Backend Implementation Contract）

> **用途**：后端工程师（任务 #3）直接照此实现，无需通读 `docs/增量架构设计.md`。
> **架构师**：高见远（Gao）　**对齐**：`docs/增量PRD-v2.md` §4/§6 + `docs/增量架构设计.md`
> **包基**：`com.ecommerce.dashboard`（Spring Boot 3.2 + JDK17 + Spring Data JPA）

---

## 0. 全局约束（必读）

1. **数据源**：默认 **H2 文件库** `jdbc:h2:file:./data/dashboard`；保留 `application-mysql.properties` + `import-mysql.sql` 作可选 MySQL profile。JPA 层不得绑定 H2 方言。
2. **统一响应**：所有接口返回 `ApiResponse<T> { int code; String message; T data }`，成功 `code=200`，失败 `code=401/500` + `message`。
3. **不破坏既有契约**：现有 8 个接口（`/api/orders/*`）的**路径、DTO、字段**保持不变；仅 `OrderController` 各方法**新增可选 `sellerId` 参数**（默认 `null`=全平台），`KpiDTO` **追加** `repurchaseRate/avgReviewScore/delayRate/cancelRate` 四个字段（前端暂可不展示）。
4. **金额单位**：聚合原始 R$ 后 `/10000` 转「万 R$」返回，与现有前端一致。
5. **中文映射**：品类名（en→zh）、支付方式（en→zh）在 Service 层统一转换，前端不改。
6. **多卖家切片**：所有分析查询支持可选 `sellerId`；以 `order_items.seller_id` 作「店铺」代理（Olist 无店铺字段，诚实标注）。

## 1. 新增接口契约（4 个核心 + 1 个辅助）

所有新接口 base = `http://localhost:8080/api`，统一包 `ApiResponse<T>`。

### 1.1 `POST /api/auth/login` —— 真实登录校验（轻量）
| 项 | 内容 |
|----|------|
| 请求体 | `LoginRequestDTO { String username; String password; }` |
| 处理 | 查 `t_user` 比对口令（明文或简单哈希均可）；通过则生成 UUID `token` 存入内存 `Map<token,username>`（应用级 Session，无需 Redis） |
| 响应 | `LoginResponseDTO { String token; String username; String displayName; String role; }` |
| 失败 | `code=401, message="用户名或密码错误"` |
| 拦截 | `LoginInterceptor` 仅对 `/api/diagnosis`、`/api/signals`、`/api/alerts` 校验请求头 `X-Token`；现有 `/api/orders/**` 保持公开 |

### 1.2 `GET /api/diagnosis` —— 经营健康度诊断（规则引擎）
| 项 | 内容 |
|----|------|
| 参数 | `startDate`(yyyy-MM-dd 可选)、`endDate`(可选)、`sellerId`(可选)、`granularity`(month/week/day，默认 month) |
| 请求头 | `X-Token`（来自 login） |
| 响应 | `DiagnosisDTO`（见 §2.1） |
| 说明 | 服务端用 `RuleConfig` 阈值逐指标比对 → 生成 `signals[]` + 模板拼装 `conclusionText` |

### 1.3 `GET /api/signals` —— 补货/促销代理信号
| 项 | 内容 |
|----|------|
| 参数 | `startDate`(可选)、`endDate`(可选)、`sellerId`(可选) |
| 请求头 | `X-Token` |
| 响应 | `List<CategorySignalDTO>`（见 §2.3） |
| 说明 | 每品类按「销售增速 × 口碑 × 占比」分位映射 action；**字段 `note` 强制="基于销售趋势推测，非实时库存"** |

### 1.4 `GET /api/alerts` —— 异常预警
| 项 | 内容 |
|----|------|
| 参数 | `startDate`(可选)、`endDate`(可选)、`sellerId`(可选) |
| 请求头 | `X-Token` |
| 响应 | `List<AlertDTO>`（见 §2.4） |
| 说明 | 触发规则：品类销售额环比骤降>30% / 评分环比骤降>0.5 / 某支付方式占比突变 |

### 1.5 `GET /api/sellers` —— 卖家（店铺）预设列表（支撑视角切换）
| 项 | 内容 |
|----|------|
| 参数 | 无（或 `limit` 默认 5） |
| 响应 | `List<SellerDTO>`（见 §2.6）：`sellerId, shopName(城市+州), city, state, orderCount` |
| 说明 | 按 `t_order_item` 聚合 `COUNT(DISTINCT order_id)` 取前 5 名卖家作演示店铺 |

## 2. DTO 字段规格

### 2.1 DiagnosisDTO（/api/diagnosis 的 data）
| 字段 | 类型 | 含义 | 示例 |
|------|------|------|------|
| period.start | String | 周期起（yyyy-MM-dd） | "2018-08-01" |
| period.end | String | 周期止 | "2018-09-01" |
| period.label | String | 周期文案 | "所选周期" |
| kpi.totalSales | Double | 总销售额（万 R$） | 1359.0 |
| kpi.salesGrowth | Double | 销售额环比 % | 12.8 |
| kpi.repurchaseRate | Double | 复购率 %（复购unique÷总unique） | 18.0 |
| kpi.avgReviewScore | Double | 平均评分（0-5） | 4.1 |
| kpi.delayRate | Double | 物流延误率 %（实际>预计占比） | 8.5 |
| kpi.cancelRate | Double | 退单率 %（canceled÷总） | 2.3 |
| signals | List\<SignalDTO\> | 信号标签数组 | 见 2.2 |
| conclusionText | String | 服务端拼装的人话结论 | "本期销售额 ¥1359 万，环比 +12.8%（增长强劲）…" |

### 2.2 SignalDTO（diagnosis.signals 元素）
| 字段 | 类型 | 含义 | 取值 |
|------|------|------|------|
| code | String | 信号编码 | SALES_GROWTH_STRONG / REPAIR_LOW / REVIEW_LOW / DELAY_HIGH / CANCEL_HIGH 等 |
| level | String | 语义色 | green / gray / red / orange |
| label | String | 信号名 | 增长强劲 / 拉新不足 / 口碑预警 / 物流预警 / 退单预警 |
| metric | String | 指标名 | 销售额环比 / 复购率 / 平均评分 / 物流延误率 / 退单率 |
| value | String | 实际值 | "+12.8%" / "18%" / "3.4" |
| threshold | String | 触发阈值 | ">+10%" / "<20%" / "<3.5" |

### 2.3 CategorySignalDTO（/api/signals 元素）
| 字段 | 类型 | 含义 |
|------|------|------|
| category | String | 品类中文名 |
| categoryEn | String | 品类英文名 |
| growthRate | Double | 销售增速 %（本期 vs 上期） |
| avgScore | Double | 口碑评分（0-5） |
| share | Double | 该品类销售额占比 % |
| action | String | 重点投入 / 观察 / 促销去化 |
| note | String | 固定 "基于销售趋势推测，非实时库存" |

### 2.4 AlertDTO（/api/alerts 元素）
| 字段 | 类型 | 含义 |
|------|------|------|
| type | String | 预警类型：CATEGORY_DROP / SCORE_DROP / PAYMENT_SHIFT |
| severity | String | 严重度：red / orange |
| title | String | 预警标题 |
| detail | String | 明细说明 |
| relatedCategory | String | 关联品类（无则空） |

### 2.5 LoginRequestDTO / LoginResponseDTO
- `LoginRequestDTO { String username; String password; }`
- `LoginResponseDTO { String token; String username; String displayName; String role; }`

### 2.6 SellerDTO（/api/sellers 元素）
| 字段 | 类型 | 含义 |
|------|------|------|
| sellerId | String | 卖家 ID（店铺代理） |
| shopName | String | 店铺名（如 "圣保罗-SP 店" = city + "-" + state） |
| city | String | 城市 |
| state | String | 州 |
| orderCount | Long | 订单数（用于排序取 top5） |

## 3. 数据库契约（DDL）

> 表名统一 `t_` 前缀（规避 H2/MySQL 保留字 `ORDER`）。所有表 `CREATE TABLE IF NOT EXISTS`。

```sql
CREATE TABLE IF NOT EXISTS t_order (
    order_id                  VARCHAR(32)  PRIMARY KEY,
    customer_id               VARCHAR(32),
    order_status              VARCHAR(20),
    purchase_timestamp        TIMESTAMP,
    approved_at               TIMESTAMP,
    delivered_carrier_date    TIMESTAMP,
    delivered_customer_date   TIMESTAMP,
    estimated_delivery_date   TIMESTAMP
);

CREATE TABLE IF NOT EXISTS t_order_item (
    order_id            VARCHAR(32)  NOT NULL,
    order_item_id       INT          NOT NULL,
    product_id          VARCHAR(32),
    seller_id           VARCHAR(32),
    shipping_limit_date TIMESTAMP,
    price               DECIMAL(12,2),
    freight_value       DECIMAL(12,2),
    PRIMARY KEY (order_id, order_item_id)
);

CREATE TABLE IF NOT EXISTS t_payment (
    order_id             VARCHAR(32) NOT NULL,
    payment_sequential   INT         NOT NULL,
    payment_type         VARCHAR(20),
    payment_installments INT,
    payment_value        DECIMAL(12,2),
    PRIMARY KEY (order_id, payment_sequential)
);

CREATE TABLE IF NOT EXISTS t_review (
    review_id                VARCHAR(32) PRIMARY KEY,
    order_id                 VARCHAR(32),
    review_score             INT,
    review_comment_title     VARCHAR(255),
    review_comment_message   CLOB,
    review_creation_date     TIMESTAMP,
    review_answer_timestamp  TIMESTAMP
);

CREATE TABLE IF NOT EXISTS t_customer (
    customer_id         VARCHAR(32) PRIMARY KEY,
    customer_unique_id  VARCHAR(32),
    zip_code_prefix     VARCHAR(10),
    customer_city       VARCHAR(64),
    customer_state      VARCHAR(8)
);

CREATE TABLE IF NOT EXISTS t_product (
    product_id           VARCHAR(32) PRIMARY KEY,
    category_name        VARCHAR(64),
    name_length          INT,
    description_length   INT,
    photos_qty          INT,
    weight_g             INT,
    length_cm            INT,
    height_cm            INT,
    width_cm             INT
);

CREATE TABLE IF NOT EXISTS t_seller (
    seller_id        VARCHAR(32) PRIMARY KEY,
    zip_code_prefix  VARCHAR(10),
    seller_city      VARCHAR(64),
    seller_state     VARCHAR(8)
);

CREATE TABLE IF NOT EXISTS t_category_translation (
    category_name           VARCHAR(64) PRIMARY KEY,
    category_name_english   VARCHAR(64)
);

-- 用户表（非 Olist，登录用）
CREATE TABLE IF NOT EXISTS t_user (
    username      VARCHAR(32) PRIMARY KEY,
    password      VARCHAR(64),
    display_name  VARCHAR(64),
    role          VARCHAR(20)
);

-- 演示账号初始化
INSERT INTO t_user (username, password, display_name, role)
SELECT 'demo','demo123','演示店主','SELLER' WHERE NOT EXISTS (SELECT 1 FROM t_user WHERE username='demo');
INSERT INTO t_user (username, password, display_name, role)
SELECT 'admin','admin123','数据管理员','ADMIN' WHERE NOT EXISTS (SELECT 1 FROM t_user WHERE username='admin');

-- 推荐索引（加速切片与聚合）
CREATE INDEX IF NOT EXISTS idx_oi_seller   ON t_order_item(seller_id);
CREATE INDEX IF NOT EXISTS idx_o_status    ON t_order(order_status);
CREATE INDEX IF NOT EXISTS idx_o_purchase ON t_order(purchase_timestamp);
CREATE INDEX IF NOT EXISTS idx_r_order    ON t_review(order_id);
CREATE INDEX IF NOT EXISTS idx_r_score    ON t_review(review_score);
```

**CSV 导入（H2 默认）**：`DatabaseInitializer`（`@ApplicationRunner`）在 `SELECT COUNT(*) FROM t_order = 0` 时，用 `CSVREAD('${import.csv-path}olist_xxx.csv', NULL, 'charset=UTF-8')` 执行各表 `INSERT ... SELECT`，时间戳 `PARSEDATETIME(NULLIF(col,''),'yyyy-MM-dd HH:mm:ss')`。`geolocation`（100 万行）**不导入**。

## 4. RuleConfig 阈值表（写在 application.properties，经 `@ConfigurationProperties("datarule")` 注入）

| 配置键 | 值 | 对应信号 | 来源 |
|--------|-----|---------|------|
| datarule.sales-growth-strong | 10 | 销售额环比 >+10% → 增长强劲(绿) | PRD §4 |
| datarule.sales-growth-decline | -10 | < -10% → 下滑预警(红)；-10%~+10% → 平稳(灰) | PRD §4 |
| datarule.repurchase-low | 20 | 复购率 <20% → 拉新不足(橙) | PRD §4 |
| datarule.review-low | 3.5 | 平均评分 <3.5 → 口碑预警(红) | PRD §4 |
| datarule.review-high | 4.2 | ≥4.2 → 口碑优秀(绿) | PRD §4 |
| datarule.delay-high | 15 | 物流延误率 >15% → 物流预警(橙) | PRD §4 |
| datarule.cancel-high | 5 | 退单率 >5% → 退单预警(红) | PRD §4 |
| datarule.alert-category-drop | 30 | 品类销售额环比骤降 >30% → 预警 | PRD §4 P1-2 |
| datarule.alert-score-drop | 0.5 | 评分环比骤降 >0.5 → 预警 | PRD §4 P1-2 |

> 阈值集中配置，便于答辩演示「调阈值→结论变」。

## 5. 派生指标计算口径（实现参考）

| 指标 | 计算 SQL 思路 |
|------|--------------|
| 销售额 | `SUM(oi.price)`（join t_order） ÷ 10000（万） |
| 销售额环比 | (本期 SUM - 上期 SUM) / 上期 SUM ×100；上期=同粒度前一段 |
| 复购率 | `COUNT(DISTINCT c.customer_unique_id HAVING COUNT(DISTINCT o.order_id)>1)` ÷ `COUNT(DISTINCT c.customer_unique_id)` |
| 平均评分 | `AVG(r.review_score)` |
| 物流延误率 | `COUNT(o.delivered_customer_date > o.estimated_delivery_date)` ÷ `COUNT(delivered 订单)` |
| 退单率 | `COUNT(order_status='canceled')` ÷ `COUNT(*)` |
| 店铺切片 | 所有聚合加 `JOIN t_order_item oi ... WHERE (:sid IS NULL OR oi.seller_id=:sid)` |
| 当前周期 | 以 `MAX(purchase_timestamp)`（≈2018-09）为基准，前端/接口统称「所选周期」 |

## 6. 后端实现顺序建议（对应架构设计 T0–T8）

1. **T0** 数据源改 H2 + `schema.sql` + `DatabaseInitializer`（CSVREAD 自举导入）
2. **T1** 11 个实体（含 `OrderItemId`/`PaymentId` 联合主键）+ 9 个 Repository（含聚合 `@Query`）
3. **T2** `JpaOrderServiceImpl(@Primary)` 替换 Mock（`MockOrderServiceImpl` 加 `@Profile("mock")`）；中文/支付映射；`sellerId` 切片；`OrderController` 加 `sellerId` 参数；`KpiDTO` 加 4 字段
4. **T3** `t_user` + `UserRepository` + `AuthController`/`AuthService` + `LoginInterceptor`/`WebConfig`
5. **T4** `RuleConfig` + `DiagnosisService`/`Controller` + `DiagnosisDTO`/`SignalDTO`
6. **T5** `SignalsService`/`AlertsService` + Controllers + `CategorySignalDTO`/`AlertDTO`
7. **T6** `SellerController` + `SellerDTO`（top5 预设）
8. **T8** Swagger 核对真实数据 + 数据一致性（看板数字 vs 库）
