## 1. 全局 fetch 封装（auth.js 提供，统一调用）

```javascript
// dashboard/assets/auth.js
const API_BASE = 'http://localhost:8080/api';
const TOKEN_KEY = 'datapk_token';

export function getToken()  { return sessionStorage.getItem(TOKEN_KEY); }
export function setToken(t) { t ? sessionStorage.setItem(TOKEN_KEY, t) : sessionStorage.removeItem(TOKEN_KEY); }

// 统一请求：自动带 X-Token；3s 超时；401 跳登录；网络错误 toast
export async function apiFetch(path, { method = 'GET', body = null, needAuth = false } = {}) {
  const headers = { 'Content-Type': 'application/json' };
  if (needAuth) {
    const t = getToken();
    if (!t) { location.href = 'welcome.html'; throw new Error('未登录'); }
    headers['X-Token'] = t;
  }
  const res = await fetch(API_BASE + path, {
    method,
    headers,
    body: body ? JSON.stringify(body) : null,
    signal: AbortSignal.timeout(3000)
  });
  if (res.status === 401) { setToken(null); location.href = 'welcome.html'; throw new Error('登录失效'); }
  if (!res.ok) throw new Error('HTTP ' + res.status);
  const json = await res.json();
  return json.data;   // 统一 ApiResponse<T>.data
}
```

**错误处理规范**：
- 超时（AbortSignal 3s）/ 网络错误 → `showToast('数据加载失败，请确认后端已启动', 'error')`。
- 401 → 清 token 并跳 `welcome.html`（仅受保护接口触发）。
- 业务错误（`json.code !== 200`）→ toast 展示 `json.message`。

## 2. 接口路径清单（前端需调用的全部）

| 用途 | 方法 + 路径 | 需 X-Token | 响应 DTO |
|------|------------|-----------|----------|
| 品类列表 | `GET /orders/categories` | 否 | `List<String>`（中文） |
| KPI | `GET /orders/kpi?category=&startDate=&endDate=&sellerId=` | 否 | `KpiDTO` |
| 趋势 | `GET /orders/trend?...&granularity=month&sellerId=` | 否 | `TrendDTO` |
| 品类排行 | `GET /orders/category-rank?...&sellerId=` | 否 | `List<CategoryRankDTO>` |
| 商品 TOP | `GET /orders/product-ranking?...&sellerId=` | 否 | `List<ProductRankDTO>` |
| 支付分布 | `GET /orders/payment-distribution?...&sellerId=` | 否 | `List<PaymentDistributionDTO>` |
| 用户分布 | `GET /orders/user-distribution?...&sellerId=` | 否 | `UserDistributionDTO` |
| 订单分页 | `GET /orders?...&sellerId=` | 否 | `PageResult<OrderDTO>` |
| **登录** | `POST /auth/login` | 否 | `LoginResponseDTO` |
| **诊断** | `GET /diagnosis?startDate=&endDate=&sellerId=` | **是** | `DiagnosisDTO` |
| **信号** | `GET /signals?startDate=&endDate=&sellerId=` | **是** | `List<CategorySignalDTO>` |
| **预警** | `GET /alerts?startDate=&endDate=&sellerId=` | **是** | `List<AlertDTO>` |
| **卖家列表** | `GET /sellers` | 否 | `List<SellerDTO>` |

> `sellerId` 留空 = 全平台；切换店铺时所有列表/图表接口追加 `&sellerId=xxx`。

## 3. 时间口径与文案

- 全站统一用「**所选周期**」措辞，不写「本月/本周」。
- 默认起止：以数据集最大日期（Olist≈2018-09）为「当前」，默认展示最近 3–6 个月；筛选器提供快捷区间（近 30 天/90 天/全部历史）映射到实际日期。
- 看板可标注「数据截至 2018-09 · Olist 巴西电商真实数据集（约 10 万订单）」增强可信度。

const data = await apiFetch('/diagnosis?startDate=&endDate=&sellerId=' + curSeller, { needAuth: true });

const alerts = await apiFetch('/alerts?...&sellerId=' + curSeller, { needAuth: true });

## 7. welcome.html 登录态串联（auth.js）

**页面要素**：品牌名 DataPeak + **Slogan「看不懂 Excel 也能看懂生意」** + 三类用户（女装店主/代运营/经销商）一键进入 + 登录表单（演示账号提示）。

**登录流程**：
```javascript
// welcome.html 登录提交
form.addEventListener('submit', async (e) => {
  e.preventDefault();
  const req = { username: u.value, password: p.value };
  try {
    const r = await apiFetch('/auth/login', { method: 'POST', body: req });
    setToken(r.token);                 // 存 sessionStorage
    sessionStorage.setItem('dp_user', r.displayName);
    location.href = 'index.html';      // 跳转看板
  } catch (err) {
    showToast('用户名或密码错误（演示账号 demo / demo123）', 'error');
  }
});
```
- 三类用户「一键进入」为演示快捷按钮，点击即填入对应演示账号并提交登录（不强校验多权限）。
- 进入 `index.html` 后，受保护接口（diagnosis/signals/alerts）自动带 `X-Token`；若 token 缺失/失效由 §1 拦截跳回 welcome。

## 9. seller 视角切换交互（seller-switch.js）

**DOM**：看板首页筛选区新增下拉（与品类/时间并列）：
```html
<div class="filter-group"><span class="filter-label">店铺视角</span>
  <select class="filter-select" id="sellerView"><option value="">全部平台</option></select>
</div>
```
**逻辑**：
```javascript
const sellers = await apiFetch('/sellers');   // 无需 token
const sel = document.getElementById('sellerView');
sel.innerHTML = '<option value="">全部平台</option>' +
  sellers.map(s => `<option value="${s.sellerId}">${s.shopName}</option>`).join('');
sel.onchange = () => {
  curSeller = sel.value;          // 全局当前店铺
  loadDashboard();                // 重新拉取所有看板接口（带 &sellerId=）
};
```
- `curSeller` 为空 = 全平台；切换后所有 `apiFetch` 的 `sellerId=` 参数随之变化，看板数字/诊断/信号/预警整体切片到该店铺。
- 预设卖家由后端 `/sellers` 返回 top5（城市+州作店名），Olist 无店铺字段，前端下拉文案即 `shopName`。

## 11. 与后端契约的边界（务必一致）

- 受保护接口（diagnosis/signals/alerts）必须带 `X-Token`，否则 401。
- 所有金额单位为「万 R$」，前端直接展示 + `万 R$` 单位。
- 品类名/支付方式名后端已转中文，前端原样展示即可，不二次映射。
- 商品名后端为「中文品类 + # + product_id 后 6 位」合成（Olist 无商品名字段），前端表格/排行照常渲染。
- 时间字段 `purchaseTime` 格式 `yyyy-MM-dd HH:mm`，前端按现有逻辑展示。
